# 揭示一格：逐步提示模式 設計

## 背景與目的

目前「揭示一格」只用 toast 顯示最後一步，例如「唯一候選數：第 r 列第 c 欄 = v」。但解出那一格之前，常常要先用其他技巧消去候選數，例如數對、Wing。這些步驟被 `TechniqueSolver.nextAssignment`（`src/domain/solver/TechniqueSolver.ts:59-74`）默默套用後丟掉，玩家只看到答案，看不到「為什麼」。

另外兩個問題也會讓提示看起來像在亂講：
- **推理不看玩家的筆記**：推理用的是盤面算出來的真實候選數。玩家的筆記可能沒寫、不完整，甚至寫錯。
- **填錯的格子被直接忽略**：`Sudoku.buildEffectiveNumberBoard`（`src/domain/game/Sudoku.ts:209-226`）把填錯的格子當成空格，提示可能跟玩家眼前那個錯的數字互相矛盾。

**目標**：讓「揭示一格」變成在盤面上一步步展示完整推理的提示模式，不管玩家的筆記或填寫狀態如何，看到的推理都對得上。

## 目標

- 按「揭示一格」進入盤面上的提示模式，依序展示從目前局面到下一個填入數字的完整推理：所有消去步驟，加上最後的填入步驟。
- 玩家可以前後翻看步驟；最後一步才能「填入答案」。
- 盤面有填錯的格子時，這次提示只指出**一格**錯誤，就此結束，不接著推理；沒有填錯的格子時，才進入逐步推理。
- 提示中的候選數一律用解題器算出的真實候選數，跟玩家筆記在視覺上明確區分。
- 提示選單拿掉「檢查錯誤」，因為揭示一格已經涵蓋這個功能。

## 非目標

- 不改「解題演示」頁本身的行為。
- 不改提示次數規則：每局最多 4 次，第一次免費。
- 不做「填錯立即標示」模式（使用者明確不要）。
- 不改「自動筆記」、「檢查衝突」的行為。

## 反目標（技術上能動，但這樣就算失敗）

- 提示說「刪去某格的 3」，但畫面上那格看不到 3，或看不出跟哪些格子有關。
- 玩家沒發現後面還有步驟，就在中途把答案填了。
- 玩家自己的筆記被提示模式永久改掉；唯一的例外是「填入答案」後刪掉已證明不可能的候選數。
- 提示幫玩家「補」上沒寫的筆記。
- 我們自己產生的題目走到「找不到技巧、只好隨機揭示」。

## 已決定事項（使用者）

| 主題 | 決定 |
|---|---|
| 呈現方式 | 盤面上的小型解題演示，一步步翻看（原型 A） |
| 按鈕 | 只有最後一步顯示「[答案數字] 填入答案」；前面的步驟顯示「下一步」 |
| 筆記 | 提示模式中，推理用到的格子顯示「算出的候選數」，玩家筆記暫時隱藏，結束後還原 |
| 填入後的筆記 | 只「刪」不「補」：提示中刪去的候選數，若在玩家筆記裡就刪掉；其他筆記不動，也不補上沒寫的 |
| 填錯的格子 | 一次提示是「指出一格錯誤」或「逐步揭示一格」二選一。有錯時只指出一格，面板說明這格填錯了，提供「清除」與「關閉」，不接著揭示（使用者：避免錯很多格時一次給太多提示） |
| 檢查錯誤 | 從提示選單拿掉，因為揭示一格是它的加強版 |
| 提示消耗 | 提示一出現就算消耗，就算按取消或沒看完 |
| 檢查衝突 | 保留 |
| 找不到技巧時 | 維持隨機揭示並說明；我們自己產生的題目不允許走到這一步，外部題目可以 |
| 畫面設計 | 以可操作原型（`spike/hint-mode`，commit 8a91d2b）為準，使用者試過並認可，只改了上面的按鈕規則 |

## 設計

### 1. 推理步驟的產生與套用（domain）⚙︎

- 現有的 `Sudoku.revealCellWithTechnique()` 會直接改盤面。改成兩個操作：
  - 唯讀的「計算提示」：有錯格時回傳要指出的那一格錯誤；沒有時回傳步驟清單，以及找不到技巧時的後備目標。
  - 「套用提示」：只在按下填入答案時呼叫。
- `RevealOutcome`、`onHintReveal` 和提示結果 toast 照新流程調整：toast 只留給後備的隨機揭示，或直接用面板呈現。相關的舊測試要跟著改寫。
- 有錯格時永遠先走「指出一格錯誤」，所以後備的隨機揭示不會覆蓋錯的格子。

- 新增一個取得「到下一個填入為止的所有步驟」的方法，例如 `TechniqueSolver.stepsToNextAssignment(state): SolveStep[]`。它回傳依序套用的消去步驟，加上最後一個含 assignment 的步驟；找不到時回傳空陣列。`nextAssignment` 可以改成用它實作。
- 推理的起點盤面：題目給的數字，加上玩家**填對**的數字。玩家的筆記不參與推理。
- 找出填錯的格子：玩家有填、但跟答案不同的格子，可以沿用現有的檢查錯誤邏輯（`Sudoku.checkErrors`），依閱讀順序取第一格。
- 每一步給畫面用的資料：
  - `SolveStep` 本身（`technique`、`assignments`、`eliminations`、`scopes`、`chainLinks`）
  - 該步驟開始前，相關格子的真實候選數（逐步套用前面的消去後的 `BoardState`）

### 2. 提示流程

1. 選單選「揭示一格」，立刻扣一次提示（`hintTracker.useHint()`，沿用現有流程），並送出 `hint_used`（hint_type = `reveal_cell`）。
2. **有填錯的格子時**，這次提示只處理一格錯誤：
   - 盤面用紅色標出**一格**填錯的格子。有多格錯誤時，依閱讀順序（由上而下、由左而右）選第一格 ⚙︎。
   - 面板說明「第 r 列第 c 欄填錯了」，按鈕是「清除」和「關閉」。
   - 按「清除」：清除那一格的填寫並結束提示，那格原本存著的筆記保留。按「關閉」：結束提示，盤面不變。兩種都算用掉一次提示。
   - 不會接著進入推理步驟；要揭示答案，玩家得再用一次提示。
3. **沒有填錯的格子時，進入推理步驟**：
   - 步驟 1 到 N-1 是消去，第 N 步是填入。
   - 面板有技巧名稱標籤、步驟點點、‹ › 前後翻看、白話說明、「取消」，以及主要按鈕。
   - 主要按鈕在前面的步驟是「下一步」，最後一步才是「[答案數字] 填入答案」。
4. **填入答案時**：
   - 填入目標格。
   - 提示中刪去的候選數，若在玩家筆記裡就刪掉。
   - 玩家其他的筆記還原。
   - 若有開啟「自動移除筆記」設定，照現有規則移除同行列宮的筆記。
   - 檢查是否完成，以及完成一行／列／宮的動畫。
5. **找不到任何技巧時**：沿用隨機揭示，用面板或 toast 說明「這一步沒有可用的技巧，直接揭示一格」。只有在沒有錯格時才會走到這裡。

### 3. 視覺規則（依原型）

- **盤面不動**：提示面板取代數字鍵與控制列的位置；標頭的難度標籤改成「提示模式」標籤。
- **候選數**：
  - 只在推理用到的格子顯示算出的候選數，用主題色粗體。
  - 玩家筆記在提示模式中隱藏。
  - 面板底部一行小字：「顯示盤面算出的候選數，你的筆記暫時隱藏」。
- **顏色**：
  - 淡色底：這一步作用的列、欄或宮。
  - 較深底加圓圈數字：形成圖形的格子，例如數對、Wing。
  - 紅色刪除線：要刪去的候選數。
  - 外框：答案格。
  - Wing 和鏈在格子之間畫線，沿用 `ChainOverlay` 的做法。
- **最後一步**：技巧標籤改成實心。
- **填入那一刻**：答案格要有明顯但短暫的動畫。可沿用現有的完成閃爍，或做一個放大後回彈的效果。
- 每一步都要用 360px 寬度在中英文下檢查，不可截斷或溢出。

### 4. 每種技巧的白話說明

19 種技巧（`TechniqueId`）都要有專屬的中英文說明，不能只用通用句：
- 說明要點出「哪些格子」、「為什麼」、「所以刪去或填入什麼」。格子位置一律寫「第 r 列第 c 欄」。
- 技巧名稱照多語系設計文件的術語表。
- 文字放在 `messages/en.ts`、`messages/zh-Hant.ts`，用參數插值，不在程式裡拼字串。

### 5. 提示選單

- 拿掉「檢查錯誤」，只剩自動筆記、檢查衝突、揭示一格。
- Analytics 的 `hint_type` 不再出現 `check_errors`。型別與對照表要一併拿掉。

### 6. 套用時機、遊戲紀錄與復原 ⚙︎

- **逐步揭示**：盤面只在「填入答案」時改變，填入答案和刪除筆記一次套用。在任何一步按「取消」，盤面完全不變，提示照樣算用掉。
- **指出錯誤**：只有按「清除」才改盤面，也就是清除那一格；按「關閉」不改。
- 兩種會改盤面的情況都可以復原，快照在套用前拍。
- 遊戲回顧：逐步揭示記成一個 `hint` 步驟；清除錯格沿用現有的 `erase` 步驟紀錄，或記成 `hint`，由實作者決定，但要能在回顧中看到。
- **哪些筆記會被刪**：整串推理每一步刪去的候選數都算，只要那個數字在玩家該格的筆記裡就刪掉。筆記一律只刪不補。「自動移除筆記」設定只作用在填入格的同行、列、宮，跟現在的填入規則一樣。

### 7. 提示模式期間的狀態 ⚙︎

- **提示模式是暫時狀態，不存檔**：中途離開遊戲頁、App 被關掉或重新整理，就直接結束提示模式，提示照樣算用掉，盤面不變。`GameState` 不需要改。
- 計時器照常走，暫停規則跟現在一樣。
- 提示模式中鎖住盤面：點格子、數字鍵、復原、筆記與擦除模式、提示選單都沒有作用，只能操作提示面板。
- 只有直式手機這一種版面，要在 360px 寬度確認。

### 8. 題目保證

- 目前產生器（`SudokuGenerator.generatePuzzle`）會用 `DifficultyRater` 評定難度，最多試 30 次。
  - **漏洞**：30 次都不符合時，它直接回傳最後一個候選題目，這個題目可能連困難的技巧都解不開。
  - **修正 ⚙︎**：退而求其次時，只能接受「解題器解得開」（`rater.rate(puzzle) !== null`）的題目，必要時繼續產生直到解得開為止。難度可能跟要求不完全一樣，但一定能用技巧解開。
- 我們自己產生的題目，必須每一步都能用解題器的技巧解開。要有測試：
  - 產生的題目，從初始盤面到解完都不會卡住。
  - 從題目的任意中途局面（只填入正確數字）呼叫新的步驟方法，都能拿到至少一個含填入的步驟。
- 外部輸入的題目只出現在解題演示頁，可能用到更深的技巧，所以保留隨機揭示這個後備。
- 舊版本存下來、還在進行中的遊戲，極少數可能來自上述漏洞。這種情況也走隨機揭示的後備，不另外處理 ⚙︎。

## 測試

- **Domain**：
  - 消去步驟後才填入的局面，回傳的步驟順序與內容正確。
  - 只有填入的局面，回傳一步。
  - 解不出時回傳空陣列。
  - 填錯的格子會被正確找出。
- **提示流程**：
  - 有錯格時只指出一格（多格時是閱讀順序的第一格）、不進入推理；按清除只清那一格，按關閉盤面不變，兩者都扣一次提示。
  - 沒有錯格時才進入推理步驟。
  - 前面的步驟按鈕是「下一步」，最後一步才是「[n] 填入答案」。
  - 填入後只刪不補：玩家筆記裡被提示刪去的數字被移除，其他筆記不變，沒寫的不會被補上。
  - 提示選單沒有「檢查錯誤」。
- **說明文字**：19 種技巧在兩種語言下都有專屬說明。可以用型別保證，加一條測試確認不會出現通用句。
- **題目保證**：見第 8 節，包括產生器退而求其次時只接受解得開的題目。
- **提示期間**：盤面被鎖住；取消後盤面不變；套用後可以一次復原。

## 交給實作者決定

- 元件拆分與命名。可參考原型的 `useHintMode`、`HintPanel`、`HintLinkOverlay`、`useHintExplanation`，但要照專案規範重寫並補測試。
- 每種技巧說明的實際字句（遵守術語表）。
- 填入動畫的具體樣式。
- 原型分支 `spike/hint-mode` 只當視覺參考，不直接合併；正式實作完成後刪除。
