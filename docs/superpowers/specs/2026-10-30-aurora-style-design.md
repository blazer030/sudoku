# 極光玻璃風格設計

## 背景與目的

風格研究畫布「數獨風格研究」（https://claude.ai/artifact/72nsZrRhPbd5nfnKt8UnWE）的第六個提案「極光玻璃」已經畫完，這次照它做成正式風格 `aurora`，分支 `feature/style-aurora`。

擁有者這次沒有回答問題，只說「照黑板那次一樣寫設計規格和計劃」「寫完直接開始就好，我最後看結果就行」。所以畫布沒說清楚的地方都由我決定，集中寫在最後的「規格裁定」，內文用「（裁定 N）」標出來。

設計來源（畫布裡的檔案，用 Artifact `read` 加 `path` 取得；本機副本在 `.worktrees/style-research/docs/style-research/project/`。畫面、顏色、尺寸、動畫時序以畫板為準，這份文件只記決定與取捨）：

- `project/Aurora.dc.html`：所有頁面（首頁、遊戲、提示、完成、統計、回顧、演示、設定、更新日誌、各對話框），晨光／夜空兩種模式、四種主題色，以及填入／擦除效果。
- `project/GroupAurora.dc.html`：完成一列／欄／宮。
- `project/MomentsAurora.dc.html`：載入與過關，含減少動態的版本。
- `project/PickerC.dc.html`、`project/PickerFlow.dc.html`：外觀頁卡片（「磨砂玻璃浮在流動的極光上」「夜空／晨光・4 色」）和 App 圖示。
- `project/canvas.json`：設計筆記 `note6`、`momentsNote9`、`groupNote9`（下文引用的筆記都在這裡）。

要做出來的感覺：深夜的天空（或清晨的天光）裡飄著四團極光，所有東西都是浮在上面的磨砂玻璃。九宮是九塊分開的玻璃，宮與宮之間透出極光；選到的格子是一塊點亮的主題色玻璃，四周有柔光。

## 目標

- 新增風格 `aurora`，兩種模式改名：深色「夜空」、淺色「晨光」（`STYLE_MODE_NAMES`）。英文 Night Sky／Dawn（裁定 14）。
- **兩種模式都做**，`STYLE_COLOR_MODES.aurora = ["dark", "light"]`，用一般的 `themeBuilder`。畫板預設夜空，外觀卡片也寫「夜空／晨光」，所以深色排第一。
- **四種主題色**（畫板色票：紫、青綠、粉紅、橘）。主題 id 是 `purple`、`teal`、`pink`、`orange`，`settings.colorThemes` 裡都有這些 key（紫／青綠／粉紅／橘），不用新增 i18n。主題 id 一律在各自的風格裡查，跟 minimal 撞名沒關係。預設 `purple`。
- 主題只換強調色，極光的四個顏色和其他 token 只跟著模式換：
  - 夜空：底 `#060914`、字 `#F2F5FF`、次要字 `#B0B9D3`；極光 `#19E6A3`／`#7C4DFF`／`#1FB6FF`／`#FF6FB5`，每團 42%。
  - 夜空強調色和強調上的字：紫 `#A897FF`／`#120B30`、青綠 `#4FE3C1`／`#052A22`、粉紅 `#FF8CC6`／`#3A0820`、橘 `#FFB86B`／`#3A1E00`。
  - 晨光：底 `#EEF0F7`、字 `#151A2D`、次要字 `#48506A`；極光 `#7FE7C9`／`#B7A4FF`／`#8CCBFF`／`#FFC2A6`，每團 85%。
  - 晨光強調色：紫 `#5B3FE0`、青綠 `#0A6F61`、粉紅 `#C2185B`、橘 `#A84808`，強調上的字都是 `#FFFFFF`。
  - 玻璃的染色、邊緣和高光照畫板的 `.m-dark`／`.m-light`。密度、淡底和錯誤色依「對比度的取捨」調整，畫板的字色和強調色都不改。
- 字型（`note6`）：數字和拉丁字用 **Outfit**（已打包，也是 App 的預設字），中文用 **Noto Sans TC**（已打包，見「字型」）。
- 盤面：九宮是九塊玻璃，每宮外角圓、宮與宮之間留縫。格子是半透明玻璃，選取格是主題色實心加柔光。
- 按鍵：圓形玻璃鍵；相同數字的鍵是主題色實心加柔光。
- 背景：四團極光慢慢漂移（16–26 秒一輪），加一道斜斜的光帶。
- 填入：格子裡一圈柔光脈衝擴散，數字從一團光收成清楚的字。擦除：舊數字縮小、淡掉。
- 完成一組、載入、過關照各自的畫板做（見「專屬時刻」）。
- App 圖示：極光光暈上一塊圓角玻璃，九顆光點、中央最亮。**跟著主題色和模式換**，四色乘兩種模式共 8 張。

## 非目標

- 改動頁面結構或功能，只換外觀。「共用的小改動」列出的鉤子是例外，其他風格看起來完全不變。
- 極光跟著觸控或陀螺儀動、可調的極光強度。
- 真正的背景模糊：見「玻璃與極光怎麼畫」。

## 反目標

- 中階 Android WebView 掉格。會動的東西一律不套濾鏡（`filter`、`backdrop-filter` 都不用），只動 `transform` 和 `opacity`。
- 字讀不清楚。字壓在流動的極光上，極光正好飄到最亮的時候，字還是要過 AA。
- 三個瀏覽器長得不一樣。不用 `:has()`、不用 SVG 參照遮罩、不用 `offset-path`、不用 `digitWriter`，Chromium、WebKit、Firefox 看到同一個畫面。
- 柔光蓋住數字。填入的脈衝、選取格的光暈、完成一組的光帶都不能壓過別格的數字。

## 限制與技術決定

### 玻璃與極光怎麼畫

這是這個風格最大的技術決定（裁定 1、2、3）。

- **不用 `backdrop-filter`**，任何地方都不用，連頁首捲動後的磨砂也不用（其他風格頁首用的 `blur(calc(… * var(--header-scroll)))` 這裡不套）。
  - 原因一，效能：背景的極光一直在動，背後在動的話，玻璃就算本身不動，瀏覽器每一格都要重算模糊。遊戲畫面有盤面、十顆鍵、三個控制鍵、頁首 pill，二十多塊玻璃同時模糊，這正是 `note6`、`momentsNote9` 擔心的低階 Android 掉格。
  - 原因二，看不出差別：極光本身就是柔邊的漸層，沒有細節可以模糊，模糊前後幾乎一樣。唯一有細節的背景是對話框後面的盤面，那裡改用更密的玻璃和更深的遮罩。
  - 原因三，三個瀏覽器一致：WebKit 要前綴，Firefox 103 才支援，模糊半徑的取樣也不完全一樣。不用就沒有差異。
- **玻璃 = 半透明的染色 + 邊緣 + 高光 + 陰影**，全部是靜態的 `background-color` 和 `box-shadow`：
  - 染色：`color-mix(in srgb, var(--color-glass) <密度>, transparent)`。夜空的 `glass` 是畫板的 `rgb(20 26 52)`，晨光是白色。
  - 邊緣：`inset 0 0 0 1px`，用 `glass-sheen`（白）的 85%（晨光）／12%（夜空）。
  - 高光：`inset 0 1px 0`，同一個白的 90%／14%。
  - 陰影：`0 10px 30px -12px`，畫板的 `--shadow`。
  - 密度寫成 skin 的自訂屬性（`--aurora-glass-card`、`--aurora-glass-cell` 等），對比測試直接讀，像 paper 讀 `--paper-*` 那樣。
- **極光 = 預先柔化的漸層**：每團極光是一個 `radial-gradient(circle, <色> 0, transparent 66%)`，光帶是兩個拉長的橢圓 `radial-gradient` 疊在一起（左邊 a1、右邊 a2）。
  - 畫板光帶的 `filter: blur(30px)` 拿掉：橢圓漸層本身就是柔邊，不需要模糊。
  - 光帶做成兩個橢圓，不是「線性漸層 + 遮罩」，這樣連 `mask-image` 都不用。
- **極光放在三層固定的偽元素上**，不新增元件：
  - `body::before`：a1（左上）和 a3（左下），一起漂移（畫板 `drift1`，19 秒來回）。
  - `body::after`：a2（右中）和 a4（右下），另一條路徑（`drift2`，23 秒，反向來回）。
  - `.app-safe-area::before`：光帶（`ribbon`，16 秒來回，−12° 轉到 −4°）。
  - 三層都 `position: fixed`、`z-index: -1`、`pointer-events: none`、`will-change: transform`，只動 `transform`。
  - 兩團一層（畫板是四團各自漂移）是為了效能和對比模型（見下）。四團分兩條路徑、加上光帶的第三條，看起來還是各飄各的。
- **極光的位置和漂移幅度有一條約束**：任兩團極光的核心始終相隔至少一個衰減半徑（漸層透明處，66% 半徑），兩團的亮部永遠不疊在一起。
  - 同一層的兩團相對位置固定，所以只要排得夠開。
  - 不同層之間，靜止位置的距離扣掉兩層的漂移幅度後還是要夠遠。
  - 尺寸和位置用 `vmax`／百分比，從畫板的 390×844 換算，寬螢幕照比例放大。
  - `auroraSkin.test.ts` 讀這些自訂屬性驗證這條約束，因為對比模型靠它成立。
- **對比模型假設的背景色**（裁定 3）：「最亮的一點」＝頁面底色上一團極光的核心，再疊上光帶。
  - 夜空取最亮的 a1：`#060914` 上疊 `#19E6A3` 42%，再疊光帶的 a1（55% × 42% × 0.8 ≈ 18.5%），得到 `#107E5F`。夜空的字是淺色，背景越亮越難讀。
  - 晨光取最暗的 a2：`#EEF0F7` 上疊 `#B7A4FF` 85%，再疊光帶的 a2（45% × 85% × 0.8 ≈ 30.6%），得到 `#BDACFE`。晨光的字是深色，背景越暗越難讀。
  - 所有「玻璃上的字」都在這個背景上合成後檢查。玻璃密度越高，夜空的玻璃越暗、晨光的越亮，字都更清楚，所以最薄的那種玻璃（卡片）是下限，其他更密的玻璃一定也過。
  - 測試從 palette 的極光 token 和 skin 的密度算出這個背景，不寫死色碼。
- **字不直接壓在極光上**：頁首的返回和標題、首頁標題和副標、統計的分節標題、更新日誌的說明、計時器，這些沒有玻璃墊著的字，一律用主字色，不用次要字和強調色（裁定 4）。
  - 主字色在最亮處：夜空 4.65、晨光 8.61，都過。
  - 次要字在最亮處只有 2.59（夜空）、3.98（晨光）。
- **效能預算**：
  - 背景只有三個合成層在動。
  - 玻璃全是靜態繪製，不跟著背景重畫。
  - 會動的效果只動 `transform`、`opacity`，少數短效果動 `background-color`（完成一組的格子、過關漫光）。
  - 唯一動到繪製屬性的是填入時那一個數字的 `text-shadow`，只有一格、550ms。
  - 實作完在中階 Android（或 Chrome DevTools 4× CPU 降速）錄一段遊戲畫面確認不掉格。掉格的話先縮小極光層的尺寸，不加回模糊。
- **減少動態**：極光和光帶停在畫板的起始位置（`prefers-reduced-motion`；極光屬於環境裝飾，照 `useMotionAllowed` 的註解只看系統設定）。各效果的靜態版見下。

### 盤面的玻璃與縫

- 九宮分成九塊、格子之間留縫屬於版面，skin 不能改。所以這裡沿用格子既有的格線（細線 1px、宮線 3px，見 `BoardCell` 的 `positionClasses`），讓它們變成縫（裁定 5）：
  - 格線顏色 `--board-line`、`--board-box-line` 設成透明。
  - 格子改用 `background-clip: padding-box`，背景不畫到邊框底下。
  - 這樣細線變成 1px 的縫、宮線變成 3px 的縫，透出後面的極光。畫板是 2px／5px，差一點，但不用動版面，其他風格完全不受影響。
  - `board-grid` 的外框也設成透明。
- 每格圓角 5px；每宮四個外角 14px，需要知道哪一格是宮的哪個角。新增共用鉤子 `data-box-corner`（`top-left`／`top-right`／`bottom-left`／`bottom-right`），只掛在 36 個宮角的格子上（裁定 6）。
  - 用 `--cell-row`／`--cell-column` 加 `calc()` 也算得出來，但那要靠 `mod()`（舊 WebView 不支援）或一長串 `max()`，不好讀。
- 盤面元素（`board`）和 `board-grid` 本身沒有底色，玻璃就是每一格自己。

### 字型

- 數字、拉丁字、計時器、按鍵：Outfit，已經是 `--font-sans` 的第一順位、已打包（400–700），不用新增檔案也不用 gate。題目 500、玩家數字 600、按鍵 500、筆記 500、統計數字 700，照畫板。
- 中文：用已經打包的 Noto Sans TC（`noto-sans-tc.woff2`，184 KB，blueprint 在用，可變字重 300–600，用 `chineseText` 裁）（裁定 7）。
  - 在 `fonts.css` 另外宣告一個 family `"Aurora Sans TC"`，`src` 指向同一個檔案。同一個網址只下載一次，service worker 本來就預先快取，所以**沒有新增檔案大小**。
  - 另取名字照 CLAUDE.md 的規則，不遮住系統字體，也不讓 blueprint 的 family 名稱出現在 aurora 的 stack 裡。stack 是 `--font-aurora-sans: "Outfit", "Aurora Sans TC", "PingFang TC", "Microsoft JhengHei", sans-serif`，拉丁字和數字仍然由 Outfit 畫。
  - 畫板的標題（「數獨」、對話框標題）用 700，打包的檔案只到 600。標題改用 600，不重裁 blueprint 的檔案。差一級，在 40px 的標題上看得出一點，但不加檔案大小、不動到 blueprint。
  - 不用系統中文字：Android WebView 的系統 CJK 字重不一定齊，iOS 是蘋方，兩邊會長得不一樣。
- 照「A new typeface」做 gate：
  - `styles/aurora/fonts.ts` 寫 `syncAuroraFonts`，用 `markFontsReady`，標記 `data-aurora-fonts`，接到 `appearanceSync.ts`。
  - faces：`'400 16px "Aurora Sans TC"'`、`'600 16px "Aurora Sans TC"'`，sample `"數獨 極光"`。
  - 載入完成才把 `--font-sans` 換成 aurora 的 stack，之前先用系統字。
- 新增的中文字（模式名「夜空」「晨光」、風格名）要重新跑 `generate:fonts`，讓 Noto Sans TC 和 WenKai 的子集涵蓋，`bundledFonts.test.ts` 會檢查。

### 其他

- **線條圖示**：lucide 保持 `stroke-width: 2`、圓頭，跟畫板一樣。
- **圓角**：卡片和對話框 22px（畫板 `--radius`），按鈕 16px，pill 和 chip 全圓，數字鍵和圖示鍵是正圓。
- **WebKit**：沒有 `digitWriter`，所有效果都是 CSS，Safari／iOS 看到的跟 Chromium 一樣。
- **首頁繼續遊戲卡**：`CONTINUE_LAYOUTS.aurora = "chips"`。**盤框**：`STYLE_BOARD_FRAMES.aurora = null`。**首頁標題**：`STYLE_HOME_HEROES.aurora = "stacked"`。

## 各個畫面

- **首頁**：
  - `logo` 是一顆玻璃圓球（畫板 `.orb`）：skin 把 stacked 的 80px 方塊改成正圓、玻璃底、邊緣和高光，外面一圈 40px 的主題色柔光（35%）。
  - 裡面的九個小方塊改成圓點：方塊底色透明，各自用 `radial-gradient` 畫一顆點。單數格（四角和中央）是主題色，雙數格是字色 25%，照畫板 `.orb i:nth-child(odd)`。
  - 圓點用背景畫，不改方塊大小，所以沒有版面宣告。
  - 標題 40px、600（裁定 7）、字距 0.06em；副標 14px，用主字色（裁定 4）。
  - 繼續遊戲卡是主題色實心、強調上的字，下方有主題色 70% 的柔光陰影，上緣一道 35% 白的高光。
  - chip 是 Outfit 500。夜空的 chip 底是強調上的字 16%。晨光改成主題色混 16% 的主字色（壓暗一點），讓白字過 4.5（見「對比度」）。
  - 新遊戲卡是玻璃。難度切換的底是字色 7%，選中的那格是更亮的玻璃（晨光是純白），帶一點陰影。
  - 「新遊戲」按鈕：見裁定 10。三個入口方塊是玻璃，圖示用主題色。
- **盤面**：
  - 格子是玻璃（見「盤面的玻璃與縫」）。題目用字色 Outfit 500、21px；玩家數字用主題色 600。數字大小沿用 App 的設定。
  - 筆記 10.5px 500、次要字色；相同數字的筆記改成主題色 700。
  - 同列、欄、宮：格子的玻璃再疊一層白（夜空 9%、晨光改成 95% 白），照畫板 `--peer` 的做法，但淡一些。
  - 相同數字：主題色 8% 的淡底，數字是主題色（畫板 22%，見「對比度」）。
  - 選取格：主題色實心，數字是強調上的字。外面一圈 2px 主題色 40%，再加一圈柔光。
    - 柔光從畫板的 22px／70% 收到 10px／35%（裁定 9）。理由：光暈會畫到相鄰格上，畫板的強度會讓左上方鄰格的數字在主題色光裡看不清楚。
  - 錯誤格（`error`、`wrong`）：見裁定 8。錯誤色 10% 的淡底上疊一層錯誤色的 45° 斜紋（2px 線、4px 間距，錯誤色 10%），數字用錯誤色。
    - 錯誤格就算同時被選取，也保留斜紋和錯誤色數字，不塗成主題色實心。選取改用選取格那圈 2px 光環表示（`data-selected`）。
- **提示模式**：
  - 答案格是主題色淡底（夜空 8%、晨光 6%），內圈 2px 主題色實線，外加和選取格一樣收過的柔光。
  - 候選數用主題色 700；強調的筆記是主題色圓點配強調上的字；刪去的筆記用錯誤色劃線（1.5px）。
  - 提示 pill 是主題色實心。提示選單是玻璃，「揭示一格」用主題色。
- **按鍵與控制列**：
  - 數字鍵是 56px 正圓玻璃，Outfit 500、24px。

## 填入與擦除

- **填入**（只寫在 skin，沒有 `digitWriter`）：

  - 柔光脈衝畫在格子的 `::before`：主題色 55% 的 `radial-gradient` 從 40% 放大到 115%、從 95% 淡到 0，800ms（畫板 `pulseA`）。

  - 脈衝的 `animationend` 結束 arriving（偽元素的動畫才會結束它），800ms 在 `ARRIVAL_SETTLE_MS`（1000ms）之內。
  - 選取格的數字是強調上的字，脈衝照樣畫在主題色玻璃上，看起來是那塊玻璃亮了一下。
- **擦除**：
  - 用 `data-leaving-value` 在格子的 `::before` 畫出剛擦掉的數字，顏色是格子當下的字色。
  - 在 500ms 內從原尺寸縮到 60%、淡到 0（畫板 `fadeA`，拿掉其中的 `blur(5px)`）。它的 `animationend` 結束 leaving，不留殘影。

## 對比度的取捨

規則：文字 4.5:1、UI 元件 3:1。背景一律用「最亮的一點」：夜空 `#107E5F`、晨光 `#BDACFE`（見「玻璃與極光怎麼畫」）。

畫板的玻璃太薄：極光飄到字後面最亮的時候，多數組合不過。處理方式是加密玻璃、調淡底，**不改畫板的字色和強調色**，跟 blueprint 的做法一樣（數值在 `paletteContrast.test.ts` 的 `AURORA_BOARD_CASES` 把關）：

- **錯誤色和主題色分開**（blueprint 的教訓）：
  - 晨光畫板的錯誤色 `#C2185B` 就是粉紅主題的主題色，夜空的 `#FF6F91` 和粉紅 `#FF8CC6` 也很近（ΔE 22）。
  - 改用真正的紅：夜空 `#FF948A`、晨光 `#B71C1C`。紅剛好落在粉紅和橘之間，和兩邊的 ΔE 都約 35（晨光和橘 24），只靠顏色還不夠。
  - 所以錯誤格多一層 45° 斜紋，而相同數字只有平塗的淡底、選取是實心，三種狀態靠圖樣就分得出來。
- **選取格是主題色實心**，不是淡底加框，所以通用的「X on cell-selected」組合（強調色字在選取底上、主題色框在選取底上）對 aurora 不成立。這些組合加 `exceptIn: ["aurora"]`，寫明原因。`AURORA_BOARD_CASES` 改為檢查：
  - 強調上的字在主題色上（最低 5.84，晨光橘）；
  - 主題色實心對周圍格子的 3:1（UI 元件）；
  - 選取格光環對格子的 3:1。
- **玻璃層之間的差異**：格子、同列欄宮、相同數字是半透明的玻璃，差在亮度一點點和色相。`cell-clue vs card` 這類「層要看得出不同」的組合，像 ink、chalkboard、blueprint 一樣對 aurora 豁免，原因寫明「題目與其他格同一塊玻璃，靠字色分辨」。
- `card` token 是「卡片密度的玻璃在最亮處的合成色」（不透明），`cell-clue` 和預設格是格子玻璃的合成色，`cell-peer` 是同列欄宮的合成色。所以通用的 token 組合測試本身就是在最亮處檢查。
- 格縫和玻璃邊緣是材質，不是 UI 元件的邊界，不套 3:1。按鍵靠上面的數字辨認。

`UNRELEASED_CHANGES` 加一條「全新風格「極光玻璃」」／"New style: Aurora Glass"（兩種語言）。商店和更新日誌的文案不列出、也不計算風格數量。

## 共用的小改動（其他風格看起來不變）

- `BoardCell` 在宮角的格子上加 `data-box-corner`（裁定 6）。其他風格不讀它。
- 以上都要補上 CLAUDE.md 的「Skin hooks」說明，並在「Registering a style」記下 aurora 的 own tokens 和模式名稱（像 chalkboard、blueprint 那樣）。

其他需要的東西都用既有的鉤子：`body` 和 `.app-safe-area` 的偽元素（極光）、stacked 的 `logo`、`data-arriving`／`data-leaving-value`、`data-celebration`、`--cell-row`／`--cell-column`、`groupPlacement.ts`、`dialog-scrim`、`loader-scrim`。

## 規格裁定

畫布沒說清楚、或跟可用性衝突的地方，以下都是我的決定。

1. **不用 `backdrop-filter`**，連頁首捲動後的磨砂也不用。背景一直在動，任何背景模糊每一格都要重算。極光本身沒有細節，模糊了也看不出差別。三個瀏覽器的模糊也不一致。頁首捲動後改成頁面底色 88% 的半透明底，不模糊。
2. **極光只用預先柔化的漸層，放在三層固定偽元素上**：光帶的 `blur(30px)` 改成兩個橢圓 `radial-gradient`；四團極光兩兩一層。只動 `transform`。
3. **對比模型的背景**：「一團極光的核心加光帶」的最亮處（夜空 `#107E5F`、晨光 `#BDACFE`）。為了讓這個假設成立，規定兩團極光的核心永不重疊，由測試驗證。不這樣規定的話，兩團核心疊在一起時，連主字色都只剩 2.99（夜空），只能把極光調暗三分之一。
4. **沒有玻璃墊著的字一律用主字色**：頁首、首頁副標、統計分節標題、更新日誌說明、計時器、平常狀態的控制鍵。次要字在極光最亮處不過。
5. **宮的縫沿用既有格線**：格線透明、格子 `background-clip: padding-box`。縫是 1px／3px，比畫板的 2px／5px 窄，但不動版面。
6. **新增 `data-box-corner`**，讓每宮外角能有 14px 圓角，不用 `mod()` 或 `max()` 的長算式。
7. **中文用已打包的 Noto Sans TC，另取名 "Aurora Sans TC"，標題用 600 不用 700**：零新增檔案，不重裁 blueprint 的字檔。
8. **錯誤色改成真正的紅（夜空 `#FF948A`、晨光 `#B71C1C`），錯誤格加 45° 斜紋**：畫板晨光的錯誤色就是粉紅主題的主題色。錯誤格被選取時保留斜紋，選取改用光環表示。
9. **柔光不蓋別格的數字**：填入脈衝收在格子加縫之內（畫板溢出 12px、放大 1.9 倍）。選取格光暈從 22px／70% 收到 10px／35%。
10. **按鈕**：主要按鈕是主題色實心、強調上的字，加主題色柔光陰影（照 `GroupAurora`／`MomentsAurora` 的 `.btn.primary`）。次要按鈕是淡底配主題色字。外框按鈕是玻璃。
    - `Aurora.dc.html` 裡後寫的 `.btn{background:var(--soft)}` 蓋掉了 `.primary`，所以那張畫板的「新遊戲」看起來是淡底。我判斷那是 CSS 的先後順序造成的，不是設計意圖。
11. **「從模糊到清楚」不用濾鏡**：填入的數字用同色 `text-shadow` 收起來；擦除只縮小淡出；過關卡片只縮回淡入。
12. **載入的光環改成四團轉動的 `radial-gradient`**：取代 `conic-gradient` 加 `blur(26px)`。
13. **色票用每個模式自己的主題色**（`swatchColors` 預設），不用畫板色票上固定的 `#7C5CFF`／`#14B8A6`／`#EC4899`／`#F59E0B`。色票就會跟盤面上看到的顏色一樣，勾勾用強調上的字也一定讀得到。
14. **英文模式名 Night Sky／Dawn、風格名 Aurora Glass**：畫布沒有英文。
15. **完成一組時格子只動 `background-color`**：拿掉每格的 `box-shadow` 光暈。
16. **光帶從剛填那格往兩端拉開**，跟格子的漣漪同一個起點（畫板從中間拉開）。
17. **`groupEffectMs = 900`**：涵蓋光環和光帶。
18. **過關的湧亮畫在盤面後面**（盤面的 `::before`），從格縫和玻璃透出來。畫板把它蓋在整個畫面上，但對話框打開前沒有可以掛全螢幕光的元素；不新增鉤子。
19. **過關漫光一圈一圈擴散**：每格延遲是到中心格的棋盤距離 × 85ms，取代一宮一宮 170ms，結束時間不變。
20. **`celebrationBoardMs = 800`**：遮罩進來的時間點。

## 交給實作者決定

- 每個 token 怎麼對到 `Neutrals`／`StyleExtras` 的角色：以畫板和上面的表格為準，對比由 `paletteContrast.test.ts` 把關。
- 四團極光確切的位置、大小和漂移路徑：守住裁定 3 的約束，看起來像畫板就好。
- 開關、logo 圓點、斜紋的細節，各時刻的 easing。
- `primary-hover`、`foreground-muted`、`border` 等畫板沒畫到的 token：照同模式的鄰近值推，過對比測試即可。
- 分步順序，建議：
  1. 註冊、配色、字型，加上極光背景和玻璃，先讓風格看得到。
  2. 頁面 skin（卡片、按鍵、設定、統計）。
  3. 盤面：玻璃格、縫、`data-box-corner`、選取、錯誤斜紋。
  4. 填入、擦除。
  5. 三個時刻和圖示。
  6. 中階 Android 的效能檢查。
